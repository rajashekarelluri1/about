The Complete Formula Cheat Sheet

Every formula category an analyst needs, searchable by name or keyword. ★ marks the ones you'll genuinely use every single week.

01

Formulas & Functions, Explained

The cheat sheet above tells you what exists. This section explains why and when — the reasoning behind the formulas you'll reach for daily.

1.1 Core arithmetic & aggregation+

The functions that summarize a range. Everything else in Excel is built on top of these.

SUM(range) AVERAGE(range) COUNT / COUNTA(range) MIN / MAX(range) SUBTOTAL(function_num, range)

Use SUBTOTAL instead of SUM inside filtered tables — it ignores hidden/filtered rows automatically, which plain SUM does not.

1.2 Conditional aggregation+

Summaries that depend on a condition — the backbone of most reporting formulas.

SUMIF / SUMIFS(criteria_range, criteria, sum_range) COUNTIF / COUNTIFS(...) AVERAGEIF / AVERAGEIFS(...) MAXIFS / MINIFS(...)
// total sales for "Region = West" and "Month = Jan"
=SUMIFS(Sales, Region, "West", Month, "Jan")
1.3 Logical functions+

Branch your formulas based on conditions — used everywhere from flags to validation.

IF(test, if_true, if_false) IFS(test1, val1, test2, val2, ...) AND() / OR() / NOT() IFERROR(value, value_if_error) IFNA(value, value_if_na)
=IFS(Score>=90,"A", Score>=75,"B", Score>=60,"C", TRUE,"F")
1.4 Lookup & reference+

The single most interview-tested category. Learn XLOOKUP and INDEX/MATCH properly and you'll rarely reach for anything else.

VLOOKUP(lookup, table, col_index, [exact]) XLOOKUP(lookup, lookup_arr, return_arr, [if_not_found]) INDEX(array, row, [col]) MATCH(lookup, array, [match_type]) OFFSET / INDIRECT
// XLOOKUP: cleaner syntax, searches any direction, built-in fallback
=XLOOKUP(A2, ID_range, Name_range, "Not found")

// INDEX/MATCH: still essential — works left-lookups VLOOKUP can't
=INDEX(Name_range, MATCH(A2, ID_range, 0))

VLOOKUP can only search left-to-right and breaks when columns are inserted. INDEX/MATCH and XLOOKUP don't have either limitation — worth the switch even on older workbooks.

1.5 Text functions+

For cleaning and reshaping raw exports before they're usable.

LEFT / RIGHT / MID(text, [start], num_chars) TRIM(text) CONCAT / TEXTJOIN(delim, ignore_empty, range) SUBSTITUTE / REPLACE TEXT(value, format) TEXTSPLIT(text, delimiter)
// join first + last name, ignoring blanks
=TEXTJOIN(" ", TRUE, First, Last)
1.6 Date & time+
TODAY() / NOW() DATEDIF(start, end, unit) EOMONTH(start, months) WORKDAY / NETWORKDAYS YEAR / MONTH / DAY / WEEKDAY
// full years between two dates — common for tenure/age calcs
=DATEDIF(StartDate, TODAY(), "Y")
02

Data Cleaning & Validation

Real datasets are never analysis-ready. This is the unglamorous 60% of the job that determines whether everything downstream is trustworthy.

2.1

Remove Duplicates & Text to Columns

Data → Remove Duplicates for exact-match cleanup. Data → Text to Columns splits one field (like "City, State") into separate columns using a delimiter or fixed width.

2.2

Data Validation

Restrict cell input to a list, number range, or custom formula via Data → Data Validation. Prevents bad entries at the source instead of catching them later.

2.3

Conditional Formatting

Highlight outliers, duplicates, or thresholds visually — color scales, data bars, and icon sets turn a raw grid into a scannable diagnostic.

2.4

Flash Fill

Ctrl+E detects a pattern from one manually-filled example and applies it to the rest of the column — fast for extracting or reformatting text without a formula.

2.5

Handling blanks & errors

ISBLANK, ISERROR, and IFERROR catch broken lookups before they silently skew a summary.

2.6

Structured Tables

Ctrl+T converts a range into a Table — auto-expanding formulas, named columns, and a stable source for PivotTables and charts.

03

PivotTables & PivotCharts

The fastest way to go from a raw table to a summarized answer, without writing a single formula.

3.1 Building your first PivotTable+

Select any cell in a structured table → Insert → PivotTable. Drag fields into four zones:

RowsColumnsValuesFilters

Values defaults to SUM for numbers and COUNT for text — check this every time, it's the most common source of a "wrong" pivot.

3.2 Calculated fields & grouping+

Add a formula-driven column with PivotTable Analyze → Fields, Items & Sets → Calculated Field. Group dates into months/quarters or numbers into bins by right-clicking a row label → Group.

3.3 Slicers & Timelines+

Visual filter buttons that can control multiple PivotTables/charts at once — Insert → Slicer. Timelines do the same for date fields, with a drag-to-select range.

3.4 PivotCharts+

A chart wired directly to a PivotTable — filtering the table updates the chart automatically. Best for dashboards where the underlying data will keep changing.

04

Power Query (Get & Transform)

This is the line between "Excel user" and "data analyst." Power Query lets you build a repeatable, auditable pipeline instead of manually cleaning the same report every week.

4.1 What it replaces+

Every manual cleaning step — trimming text, removing columns, splitting fields, merging tables — becomes a recorded, re-runnable step. Refresh the source file and the entire pipeline re-executes automatically.

4.2 Core transformations+
Remove/Keep Columns Split Column Unpivot Group By Merge Queries (joins) Append Queries (stacking) Change Data Type Fill Down/Up
4.3 Merge types (joins)+

Power Query's Merge dialog maps directly to SQL joins — Left Outer, Right Outer, Full Outer, Inner, Left Anti, Right Anti. If you know SQL, this section takes ten minutes to master.

4.4 The M language+

Every click generates M code, visible in the Advanced Editor. Most analysts never write M by hand — but reading it helps you understand exactly what a query does before refreshing it against new data.

// Example of auto-generated M
let
  Source = Excel.CurrentWorkbook(){[Name="RawData"]}[Content],
  Filtered = Table.SelectRows(Source, each [Status] = "Active")
in
  Filtered
05

Power Pivot & DAX

When one flat table isn't enough — model relationships between multiple tables and write measures that recalculate correctly no matter how the report is sliced.

5.1 The Data Model+

Load multiple tables (e.g. Sales, Products, Customers) into the Data Model and define relationships between them — replacing dozens of VLOOKUPs with a single relational structure a PivotTable can query directly.

5.2 DAX essentials+
SUM / AVERAGE / COUNTROWS CALCULATE(expression, filter) FILTER(table, condition) ALL(table/column) RELATED(column)
// Total sales, ignoring any region filter — a common "% of total" building block
Total Sales AllRegions = CALCULATE([Total Sales], ALL(Region))
5.3 Time intelligence+
TOTALYTD / TOTALQTD / TOTALMTD SAMEPERIODLASTYEAR DATEADD(dates, interval, unit)

Requires a proper Date table marked as the model's date table — the single most common setup step people skip and then wonder why YTD measures break.

06

Dynamic Arrays & Modern Excel

Functions that spill results across multiple cells automatically — Microsoft 365's biggest quiet upgrade to how formulas work.

6.1 FILTER, SORT, UNIQUE+
// all "West" region rows, sorted by revenue descending — one formula, no helper columns
=SORT(FILTER(Data, Region="West"), 3, -1)

// distinct list of customers
=UNIQUE(CustomerColumn)
6.2 LET & LAMBDA+

LET names intermediate values inside one formula, avoiding repeated sub-calculations. LAMBDA lets you define a reusable custom function without VBA.

// LET: compute once, reference twice
=LET(total, SUM(Sales), avg, total/COUNT(Sales), total & " / " & avg)
6.3 Spill ranges+

Reference an entire spilled result with a trailing # — e.g. =SUM(A2#) sums everything a dynamic array spilled from A2, and auto-adjusts as it grows or shrinks.

07

Macros & VBA

For repetitive tasks no built-in feature covers — formatting a weekly report, looping through files, or building a custom function.

7.1 Recording your first macro+

Developer → Record Macro, perform the steps once, stop recording. Excel writes the VBA for you — a good way to learn the syntax by reading what your own actions generated.

7.2 A simple hand-written macro+
' Loops through Column A and flags values over 1000
Sub FlagHighValues()
  Dim i As Integer
  For i = 2 To Cells(Rows.Count, 1).End(xlUp).Row
    If Cells(i, 1).Value > 1000 Then
      Cells(i, 1).Interior.Color = RGB(169, 106, 8)
    End If
  Next i
End Sub
7.3 When to reach for VBA vs Power Query+

Power Query for data transformation and shaping. VBA for workbook-level automation — formatting, file I/O, triggering actions on events (like a button click or a sheet change), or building custom UDFs Power Query can't express.

08

Dashboard Design Principles

A technically correct dashboard that's hard to read has failed at its actual job. These are the habits that separate a "chart dump" from a usable decision tool.

8.1

One screen, one question

Every dashboard should answer a specific question at a glance. If it takes scrolling and squinting to find the headline number, it needs restructuring.

8.2

F-pattern hierarchy

Put the most important KPI top-left. Eyes scan dashboards the same way they scan a page — use that instead of fighting it.

8.3

Chart choice discipline

Line for trend over time, bar for comparison across categories, avoid 3D and pie charts with more than 4 slices — they measure worse than they look.

8.4

Consistent color language

Pick one color for "good," one for "attention," and reuse them everywhere. Random chart-to-chart palettes force the reader to relearn the legend each time.

8.5

Interactivity over duplication

One slicer-driven view beats five near-identical static charts for each region. It's also far less to maintain when the source data changes.

8.6

Label the "so what"

A number without context (target, trend, benchmark) forces the reader to do the analysis you were hired to do. Annotate it.

Suggested Learning Path

A realistic order to build these skills — each stage assumes roughly two to four weeks of applied practice, not just reading.

Weeks 1–2 — Interface & core formulas

Navigation, formatting, absolute vs relative references, SUM/AVERAGE/IF/COUNTIFS. Rebuild a report you already receive at work, from scratch.

Weeks 3–4 — Lookups & cleaning

XLOOKUP, INDEX/MATCH, Text to Columns, Data Validation, Conditional Formatting. Take a genuinely messy export and get it analysis-ready.

Weeks 5–6 — PivotTables & charts

Build the same summary three ways — manual formulas, a PivotTable, and a PivotChart — to internalize when each is the right tool.

Weeks 7–9 — Power Query

Rebuild a recurring manual cleaning process as a Power Query pipeline. This is usually the point where a repetitive weekly task drops from hours to a single click.

Weeks 10–12 — Power Pivot & DAX

Model 2–3 related tables, write your first CALCULATE measures, build a proper Date table and a YTD metric.

Weeks 13+ — Dashboards, dynamic arrays, VBA

Combine everything into one polished, interactive dashboard. Layer in FILTER/LET for cleaner formulas and a small VBA macro to automate the one manual step left.
